# Langues de l'interface

Selene parle français ; l'anglais est en cours. Ce document dit comment écrire un texte traduisible, comment
compléter une traduction, et où en est le chantier. Les décisions et leurs raisons : [ADR 24](architecture.md#adr-24--plusieurs-langues--le-français-pour-clé-un-dictionnaire-par-langue).

Deux mots qui reviennent : l'**internationalisation** (i18n) rend le code capable de parler plusieurs langues ;
la **localisation** (l10n) le fait parler une langue donnée, avec ses dates, ses pluriels et sa typographie.

## Où ça vit

| Fichier | Rôle |
|---|---|
| `src/app/i18n/index.js` | `tr`, `trp`, `trn`, `N_`, la langue en vigueur (`uiLang()`, `uiLocale()`, `applyLang`), le tri (`collate`), les langues connues (`LANGS`) et proposées (`READY_LANGS`) |
| `src/app/i18n/en.js` | le dictionnaire anglais : texte français → traduction |
| `scripts/i18n.mjs` | `npm run i18n` : relève les textes marqués, vérifie les dictionnaires, dit la couverture (`-- --missing` : la liste de ce qui reste) |
| `tests/i18n.test.js`, `tests/browser/langue.js` | le fonctionnement, et la réserve des noms `tr`, `trp`, `trn`, `N_` |

La langue est un réglage du compte (`config.lang`, synchronisé) ; vide, c'est celle de l'appareil. Seules les
langues de `READY_LANGS` sont proposées, et le sélecteur (Réglages → Apparence) n'apparaît qu'à partir de deux.

## Écrire un texte traduisible

Le texte français reste dans le code : il **est** la clé. Ce qu'un dictionnaire ne traduit pas s'affiche en français.

```js
import { N_, tr, trn, trp } from "../i18n/index.js";

tr`Pleine lune dans ${n} j.`                      // clé : « Pleine lune dans {0} j. »
trp("toast", "Annuler")                           // Undo — et trp("formulaire", "Annuler") : Cancel
trn(n, "{0} fragment", "{0} fragments")            // la forme qui convient à n, dans chaque langue
const NAMES = [N_("Nouvelle lune"), …]; tr(NAMES[i]) // une table évaluée au chargement : marquée, traduite à l'affichage
```

Règles :

- **Une phrase entière par clé.** Jamais de phrase montée en morceaux (`"Renommer des " + champ + "s"`) : l'ordre des
  mots change d'une langue à l'autre, et le « s » n'est pas un pluriel universel. Reformuler s'il le faut.
- **Les valeurs passent par `${…}`**, jamais par concaténation ; une traduction les déplace par `{0}`, `{1}`.
- **Un pluriel passe par `trn`**, jamais par `plural()` ni `${n} ${mot}s` : en français 0 est singulier, en
  anglais pluriel, et d'autres langues ont trois ou quatre formes (catégories du CLDR, par `Intl.PluralRules`).
- **Un même mot, deux sens : `trp`** avec un contexte court (`toast`, `formulaire`…), comme `msgctxt` chez gettext.
- **Rien d'autre ne s'appelle `tr`, `trp`, `trn` ou `N_`** dans `src/app` (un test y veille) : une variable locale
  de ce nom masquerait la traduction.
- **Échappement inchangé** : `tr` rend du texte, au statut du texte qu'il remplace ; ce qui vient de la personne
  passe par `esc()` avant d'entrer, comme avant.
- **Formats** : `fmt`, `money`, `collate`, `uiLocale()` ; jamais `"fr-FR"` ni `localeCompare(…, "fr")` en dur.
  La monnaie reste l'euro : la langue change sa présentation (12,00 € / €12.00), pas sa valeur.
- **Typographie** : chaque langue a la sienne dans son dictionnaire (en anglais, “ ” et pas d'espace avant « : »).
- **Libellés du noyau** : `core/` est pur et n'importe pas la traduction. Ce qu'il nomme en français (statuts
  épistémiques, types de lien, temps qu'il fait, pluies d'étoiles filantes, vents, éclipses) est marqué dans
  `src/app/lib/labels.js` (`epLabel`, `linkLabel`, `SKY_LABELS`, `windText`, `eclipseText`) ; `tests/i18n.test.js`
  vérifie que ces tables suivent celles du noyau. Une éclipse ou un vent a sa phrase entière par cas (« Partial solar
  eclipse », pas « Eclipse partial of Sun »).
- **Erreurs du noyau** : `coreError(code, message, args)` (`core/domain.js`, `core/backup.js`). Le message reste en
  français (l'assistant le lit, en résultat d'outil) ; l'interface affiche `errMsg(e)` (`lib/labels.js`), traduit par
  le code. Jamais `toast(e.message)` sur une erreur qui peut venir du noyau.
- **Erreurs des fonctions serveur** : `{ erreur, code, detail? }`. L'interface affiche `serverMsg(j, repli)`
  (`services/erreurs.js`) et décide sur `code`, jamais sur le texte (`sans-cle`, `cle`) ; `erreur` reste le repli
  d'une fonction déployée avant les codes. Un test vérifie que chaque réponse d'erreur a un code, et chaque code sa
  phrase.
- **Modèles et types de module** : leurs textes (`MODULE_TEMPLATES`, `MODULE_TYPES`) ne sont pas marqués dans le
  noyau ; `npm run i18n` les lit dans leurs tables par `localizeConfig`, la fonction qui sait lesquels de leurs
  réglages sont du texte (`statuses`, `fields`, `addLabel`…) et lesquels sont des valeurs du code (`display`,
  `entryMode`, `groups.by`). Un module se crée dans la langue de l'interface (`localTemplate`, puis
  `createFromTemplate(…, tr)`), et ses mots sont ensuite les siens : ils ne se retraduisent pas.
- **Texte enregistré dans la langue du moment** (la provenance d'une source, `origin.from` : « Dehors », « Veille »,
  « Cité par tes sources ») : il garde la langue de sa création. Pour le reconnaître ensuite, `sameText(clé, valeur)`
  (français, chaque dictionnaire, pseudo-langue), jamais `===` (la planche de lunaison compte ainsi ce qui vient du
  dehors, quelle que soit la langue de l'époque).

Ne se traduisent jamais :

- les **clés enregistrées** (`"dépense"`, `"revenu"`, les identifiants de statut) : elles gardent leur forme, une
  table d'affichage les traduit ;
- ce que la **personne a écrit** : noms de modules, statuts, catégories, notes. Un modèle (`MODULE_TEMPLATES`) est
  traduit au moment où il crée un module ; ensuite, c'est son texte à elle ;
- la **valeur d'une `<option>`** : sans attribut `value`, une option envoie son texte affiché. Traduire ce texte
  changerait la donnée enregistrée (une dépense saisie en anglais deviendrait `"expense"`). Toujours un `value`
  explicite, seul le libellé passe par `tr` (le sélecteur du budget : `value="dépense"`, `value="revenu"`) ;
- les **verdicts et clés enregistrés en toutes lettres** (`verdict: "maintenue"` d'un réexamen) : affichés par `tr`,
  jamais réécrits ;
- la **consigne de l'assistant** (`context()` de chaque type, `instructions()`) : c'est une instruction à Claude, pas
  de l'interface ; elle reste en français, et l'assistant répond dans la langue de l'interface ;
- les **libellés choisis par la personne**, même quand le code en fabrique un pluriel (`${categoryLabel}s`) ou un
  singulier (`scrapsLabel.replace(/s$/, "")`) : cette morphologie s'applique à ses mots, dans sa langue ; seule la
  phrase autour se traduit, la fabrication passe en valeur ;
- les **constantes de protocole** envoyées à un serveur : la suppression du compte envoie toujours
  `confirmation: "supprimer"` ; seul le mot que la personne tape suit la langue (`deleteWord()`, `services/auth.js`),
  et « supprimer » y reste accepté dans toutes ;
- les identifiants techniques : `data-act`, classes CSS, adresses, et le format interne de `core/agenda.js`
  (`Intl.DateTimeFormat("en-US")` y lit des heures, il n'affiche rien) ;
- ce qu'on envoie à un service dans sa langue à lui (les `keywords_fr` d'OpenAgenda, dans le radar culturel) ;
- les messages d'erreur internes jamais montrés tels quels (`state/store.js` les remplace par un état traduit,
  `registry.js` parle aux développeurs), et le détail d'un champ refusé dans une sauvegarde (« module x : provenance
  invalide »), diagnostic technique ;
- les **libellés des anciennes données** converties en modules (`migrateModules`, « Capture », « Chantier ») : écrits
  en français avant que les modules existent, ce sont désormais les mots de la personne ;
- la recherche par statut garde `statut:` ; `status:` (et le mot de la langue en vigueur) le vaut, et le libellé se
  tape en français ou dans cette langue (`status:hypothesis`, `statut:hyp`).

## Compléter une traduction

1. `npm run i18n -- --missing` : ce qui reste, avec l'endroit du code.
2. L'ajouter dans `src/app/i18n/en.js`, rangé par fichier source, la clé copiée telle quelle (valeurs en `{0}`,
   `{1}`) ; un pluriel : `{ one, other }` sous la forme singulière française ; un contexte : `"toast\u0004Annuler"`.
3. `npm run i18n` doit rester vert. Il refuse une traduction **orpheline** : corriger une virgule dans le texte
   français change la clé, il faut reporter la correction dans chaque dictionnaire.

La **pseudo-langue** `qps` (jamais proposée) affiche chaque texte passé par `tr` accentué, allongé d'un tiers et
entre ⟦ ⟧ : un texte resté nu à l'écran a échappé à la traduction, un texte coupé manquera de place dans une langue
plus longue. On la voit avec `config.lang = "qps"` dans un **jeu d'essai** (comme `tests/browser/langue.js`), jamais
sur un vrai compte : le réglage suit le compte sur tous ses appareils.

## Ajouter une langue

Une entrée dans `LANGS` (endonyme, nom en français pour l'assistant, attribut `lang`, locale de formatage), un
dictionnaire `src/app/i18n/<code>.js`, puis, une fois `npm run i18n` à 100 %, son code dans `READY_LANGS`.

## Étapes

Choix faits : l'anglais d'abord ; la langue suit le compte ; l'assistant répond dans la langue de l'interface ;
l'app de bureau (Tauri) prend celle du système pour son menu.

| Étape | Contenu | État |
|---|---|---|
| 0. Décision | ADR 24, ce document | fait |
| 1. Socle | `src/app/i18n/`, formats et tris par `Intl` dans la langue en vigueur (plus aucun `"fr-FR"` en dur), `<html lang>`, `config.lang` (compte), sélecteur caché tant qu'une seule langue, `npm run i18n` en CI, langue des navigateurs de test fixée, pseudo-langue, consigne de langue de l'assistant. Premiers textes : lune, « Annuler » (deux sens), « Enregistrer », pagination | fait |
| 2. Extraction | Lot par lot, anglais compris ; chaque lot : français identique, scénarios verts. Faits : la charpente (navigation, palette, feuilles, sigils, minuteur, squelette `shell.html`, bibliothèques), l'accueil, les réglages (et le mot de confirmation de la suppression du compte), les huit types de module (`src/app/modules/`), les fonctionnalités (`src/app/features/` : sortes, spécimen, vasculum, tensions, liaisons, dossier, dérive, carte, partage, concordance, test lunaire, sources, citations, musique, radar, agenda, Zotero, Dehors, interface de l'assistant), la scène et le ciel, bilan, planche de lunaison, recherche, passeur, écran de connexion, état de la synchronisation. Pièges de l'étape 2 : « Renommer ou fusionner des ${champ}s » est devenu « Renommer ou fusionner les groupes par
${champ} » (plus de « s » ajouté à la main) ; `plural()` (`lib/format.js`) ne sert plus qu'au cumul, sur le libellé
choisi par la personne (sa morphologie, dans sa langue) ; un même mot peut demander deux traductions (« Reprendre » : *Resume* pour le minuteur, *Pick up
where you left off* pour l'accueil, `trp("accueil", …)`).

Pièges de l'étape 3 : un test qui décidait sur le texte d'une erreur (`/refuse|clé d'API/`, l'ancienne clé de
l'assistant à effacer) aurait cessé de reconnaître le refus une fois le message traduit ; il décide désormais sur le
code. « Tâche manquant », « Note manquant » : l'accord dépendait du genre du nom de champ ; la phrase est devenue
« Tâche : à remplir », qui n'en a pas besoin.
