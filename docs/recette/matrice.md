# Matrice de traçabilité

De chaque fonctionnalité ou règle, le risque, les cas manuels qui la vérifient, les tests automatiques qui la couvrent,
la couverture réelle et ce qu'il reste à faire. Une ligne par cas manuel (le titre du cas énonce la règle), puis les
règles que seuls les tests automatiques vérifient. État au commit `848a497` (7 octobre 2026), chaque ligne de cas précisée étape par étape, les P1 le 6 octobre, les P2 et P3 le 7 ([BL-19](backlog.md#bl-19)), puis soixante-neuf cas de plus couverts automatiquement le même jour (leurs messages, ou leur dernière étape, vérifiés) ; les cas sont dans [manuels/](manuels/),
les tests dans [automatises.md](automatises.md), les actions numérotées dans [backlog.md](backlog.md).

## États de couverture

Aucun pourcentage global : une moyenne de couvertures hétérogènes ne mesure rien. Chaque ligne a un état, défini ainsi :

| État | Définition |
|---|---|
| couvert automatiquement | Chaque étape du cas a son résultat principal vérifié par un test lancé en CI à chaque PR, sur la version web, lu dans le corps du test. Le cas peut sortir d'une non-régression ciblée quand la CI est verte ; il reste dans la recette complète. |
| couvert partiellement | Des tests vérifient la règle ou une partie des étapes, avec un serveur, des services ou une coquille simulés, ou sur une seule plateforme. Le cas manuel reste nécessaire. |
| documenté pour recette manuelle | Aucun test automatique ; seul le cas manuel la vérifie. |
| non couvert | Ni test ni cas. (Aucune fonctionnalité disponible n'est dans cet état ; les fonctionnalités envisagées sont listées dans [perimetre.md](perimetre.md#cartographie-fonctionnelle), sans ligne ici.) |
| à clarifier | Le résultat attendu dépend d'une question ouverte, marquée [À ARBITRER] dans le cas. |
| hors périmètre | Ce que la recette ne juge pas (publication sur les stores, production d'images). |

**Décompte des 192 cas manuels** : 90 couvert automatiquement, 102 couvert partiellement, 0 documenté pour recette manuelle, 0 à clarifier.

## Règles vérifiées seulement par l'automatique

Des tests sans cas manuel : règles internes (ordre de chargement, encodage, bornes d'un format, outils de construction),
ou situations trop rares ou trop fines pour une recette à la main (deux appareils hors ligne en conflit, une coupure au
milieu d'une écriture, une ligne copiée sous un autre compte). Les reproduire à la main coûterait cher et prouverait moins
que le test ; si l'un d'eux tombe, la PR est bloquée par la CI.
